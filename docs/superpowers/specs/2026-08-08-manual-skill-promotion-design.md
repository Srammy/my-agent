# Skill 人工晋升设计

## 目标

对话中的 Agent 只能创建和修改 `skills/_drafts/<skillName>/` 草稿，不能把草稿晋升为正式 Skill。只有人工在 Skill 审核界面点击“批准”时，系统才立即完成晋升。

## 方案

- Agent 使用的受保护文件系统拒绝精确的 `skills/_drafts/<name>` 到 `skills/<name>` 移动，即使已有批准记录。
- 人工批准接口在同一用户草稿锁内保存带指纹的批准决定，并通过仅供审核服务使用的工作区文件系统完成移动。
- 审核列表只读取草稿和决定，不因读取而执行晋升。
- `WebApprovalGate` 不再向后台 curator 返回可执行晋升的 `Approve` 决定；批准草稿由人工接口直接完成，curator 对批准状态保持 `Defer`。
- 保留草稿指纹、用户隔离和拒绝/变更草稿后的安全校验。

## 结果

- Agent 的直接 promote 操作失败，草稿仍保留。
- 人工点击批准后，草稿移动到正式 Skill 目录。
- 即使后台 curator 或审核列表先看到批准记录，也不会自动晋升。

## 验证

- 受保护文件系统测试：已批准草稿的 Agent 移动操作失败。
- 审核服务测试：人工批准仍能完成草稿晋升；列表读取不会晋升。
- Gate 测试：已批准草稿返回 `Defer`，拒绝草稿仍返回 `Reject`。

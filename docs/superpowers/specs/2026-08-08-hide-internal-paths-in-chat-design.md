# 对话隐藏内部路径设计

## 目标

对话中不向用户展示 Skill 管理、工作区等内部文件路径。助手仍可使用“草稿”“正式 Skill”“工作区”等业务概念进行说明。

## 方案

在后端统一处理助手文本：

1. 流式事件映射时，对助手文本增量脱敏，避免新回复直接把内部路径发送到前端。
2. 历史消息转换为接口 DTO 时，对助手消息内容再次脱敏，使已有记录的展示也不暴露路径；数据库原文不迁移、不修改。
3. 用户消息、工具调用参数和工具结果事件保持原样，避免影响权限确认和调试数据。

脱敏范围只覆盖已知的内部路径前缀，例如 `skills/_drafts/`、`skills/` 下的内部 Skill 目录和 `.agentscope/workspace`；替换为面向用户的业务表述。普通用户输入中的路径不处理。

## 验证

- 事件映射测试确认助手文本增量不含内部路径。
- 历史消息 DTO 测试确认助手消息脱敏、用户消息保持原文。
- 后端测试与构建通过后重启服务，检查聊天页面的新旧消息均不显示内部路径。
